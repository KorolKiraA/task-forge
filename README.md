# TaskForge

Ядро helpdesk/ITSM-системы: **приоритетная очередь заявок** с дедлайнами по SLA, автоматической эскалацией просроченных инцидентов и метриками. Критичные инциденты всегда обрабатываются первыми — именно это отличает службу поддержки с SLA от «почтового ящика, в который пишут».

## Идея проекта

В очереди «первым пришёл — первым обслужен» заявка «обновить логотип» может оказаться раньше, чем «падает платёжный шлюз». TaskForge заменяет FIFO на **приоритетную очередь**: порядок обработки определяется критичностью, а время реакции контролируется SLA-дедлайнами.

| Механизм | Что даёт |
|---|---|
| Приоритетная очередь | критичная заявка обслуживается раньше старых некритичных |
| SLA-дедлайны | у каждого приоритета — своё время на решение (4 ч … 7 дней) |
| Автоэскалация | при каждом действии программа сообщает о просроченных заявках |
| Метрики | backlog, доля критичных, число просрочек, закрытые за сессию |

## Быстрый старт

Нужны **JDK 17+** и **Scala 3** через [scala-cli](https://scala-cli.virtuslab.org/) (`winget install VirtusLab.ScalaCLI`).

```bash
git clone https://github.com/KorolKiraA/task-forge.git
cd task-forge

scala-cli run TaskForge.scala
```

Программа стартует с четырьмя демо-заявками разных приоритетов — очередь можно изучать сразу.

## Приоритеты и SLA

Приоритет заявки выбирается при создании и определяет дедлайн:

| Приоритет | SLA | Пример |
|---|---|---|
| Critical | 4 часа | падает платёжный шлюз, недоступен прод |
| High | 24 часа | не работает важная функция у части клиентов |
| Medium | 72 часа | ошибка с обходным путём |
| Low | 168 часов (7 дней) | косметика, пожелания |

Просрочка вычисляется от текущего времени при каждом действии: заявка не может «тихо протухнуть» — при любом обращении к меню программа выводит `⚠ ЭСКАЛАЦИЯ: N заявок просрочены по SLA!`.

## Как это устроено

```
task-forge/
├── TaskForge.scala       # модель, очередь, эскалация, метрики, CLI
├── .github/workflows/ci.yml  # компиляция на каждый push
├── LICENSE
└── README.md
```

**Ключевые решения в коде:**

- `enum Priority` с параметрами: вес для сортировки и SLA в часах живут в самом приоритете, а не в разбросанных константах;
- `PriorityQueue` с явным `Ordering`: ключ сортировки `(вес приоритета, id)` — при равном приоритете побеждает FIFO;
- `case class Ticket` неизменяем: назначение инженера и завершение создают копию через `copy()`, а не мутируют запись;
- SLA проверяется дважды: `overdue` для живых заявок и отдельный вердикт «SLA выполнен / НАРУШЕН» при закрытии — по нему считается статистика качества поддержки.

## Проектные решения и ограничения

- **Очередь в памяти**, состояние не сохраняется между запусками: это ядро логики, а не готовый сервис. Персистентность — первый пункт развития.
- **Операции «назначить» и «завершить» пересобирают очередь** (`dequeueAll` + фильтр). На тысячах заявок это O(n), для ядра приемлемо; боевой вариант — хранение в Map + индекс приоритетов.
- **Время берётся системное** (`LocalDateTime.now`): ночные сдвиги часов теоретически влияют на дедлайны; для продакшена — `Instant` в UTC.
- **Нет понятия «в работе»**: заявка либо в очереди, либо закрыта. Полноценный жизненный цикл (new → assigned → in_progress → resolved) — в идеях.

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Заявка не найдена` | ID вводится числом (`1001`), без `#`; список актуальных ID — пункт 5 |
| Крякозябры вместо кириллицы | Windows Terminal, либо `chcp 65001` перед запуском |
| `scala-cli: команда не найдена` | `winget install VirtusLab.ScalaCLI`, затем переоткрыть терминал |
| Ошибка компиляции на старой Scala | код использует синтаксис Scala 3.8; обновитесь: `scala-cli update` |

## Идеи для развития

- сохранение очереди в файл/БД и восстановление при старте;
- статусы жизненного цикла: new → assigned → in_progress → resolved;
- учёт рабочего календаря в SLA (4 рабочих часа ≠ 4 астрономических);
- автоназначение: круговая раздача заявок свободным инженерам;
- метрики за период: среднее время реакции и решения по каждому приоритету;
- уведомления об эскалации в Telegram/Slack вместо строки в консоли.
